# SangeetHub

A lightweight, mobile-friendly browser music player built with the Next.js App Router. Search tracks through a configurable music provider, play browser-compatible audio previews/streams, save favorites, create local playlists, and automatically add related tracks to the queue.

## Run locally

Requirements: Node.js 20.9 or newer and npm.

```bash
npm install
cp .env.example .env.local
npm run dev
```

Open http://localhost:3000.

On Windows PowerShell, copy the environment template with:

```powershell
Copy-Item .env.example .env.local
```

Without provider settings the app runs in demo mode. The demo catalogue contains sample metadata and artwork generated by CSS; it does not pretend those sample records have playable audio.

## Connect a music provider

Set these values in `.env.local` (keep this file private and out of Git):

```dotenv
MUSIC_API_BASE_URL=https://api.your-provider.example/v1
MUSIC_API_KEY=your-private-provider-key
MUSIC_API_SEARCH_PATH=/search
MUSIC_API_RELATED_PATH=/tracks/{id}/related
MUSIC_API_AUTH_HEADER=Authorization
MUSIC_API_AUTH_PREFIX=Bearer
```

The app's server-side adapter makes these requests:

- `GET {MUSIC_API_BASE_URL}{MUSIC_API_SEARCH_PATH}?q=search-term`
- `GET {MUSIC_API_BASE_URL}{MUSIC_API_RELATED_PATH}` with `{id}` replaced by the encoded track ID

Both endpoints should return JSON as an array or as an object containing `tracks`, `results`, or `data`.

### Track fields understood by the adapter

| App field | Provider aliases accepted |
|---|---|
| `id` | `id`, `trackId`, `uri` |
| `title` | `title`, `name`, `trackName` |
| `artist` | `artist`, `artistName`, `artists[0].name` |
| `album` | `albumName`, `album.name`, `collectionName` |
| `coverUrl` | `coverUrl`, `cover_url`, `artworkUrl`, `artworkUrl100`, `album.images[0].url` |
| `streamUrl` | `streamUrl`, `stream_url`, `previewUrl`, `preview_url`, `audioUrl` |
| `durationSeconds` | `durationSeconds`, `duration_seconds`, `durationMs`, `duration_ms` |
| `genre` | `genre`, `category` |

The stream/preview URL must be an HTTP(S) audio resource that the browser is allowed to play. A catalogue API URL or a web-page URL is not an audio stream. Use only provider media that you have permission to play, and check provider terms, preview limits, and browser CORS/range-request requirements.

### Security

- Keep `MUSIC_API_KEY` server-side. Do not prefix it with `NEXT_PUBLIC_`.
- The browser calls the local Next.js endpoints `/api/music/search` and `/api/music/related`; Route Handlers proxy requests to your provider.
- The provider key is never returned in API responses.

## Features

- Search tracks by title, artist, album, or genre.
- Song cards show title, artist, album, cover art, and duration.
- Browser audio controls: play/pause, previous/next, seek, volume, shuffle, and repeat.
- Favorites saved in the current browser.
- Create playlists and add tracks to them; playlist data is stored locally.
- Related tracks are fetched and appended to the queue after playback starts.
- Responsive layout with a mobile-friendly navigation and compact player.
- Keyboard shortcut: `Ctrl/⌘ + K` focuses search; `Escape` clears it.

Favorites and playlists are browser-local. They do not sync between browsers or devices and there is no account backend in this starter.

## Deployment note

This project uses Next.js Route Handlers to keep the provider key on the server. GitHub Pages is a static host and cannot run those server endpoints. Run locally with Node.js, or deploy the Next.js project to a Node.js-capable host such as Vercel and configure the same environment variables there. The previous static HTML/CSS/JavaScript files are still in the repository for reference; the Next.js app entry point is `app/page.tsx`.

## Current provider status

No third-party music provider is preconfigured. The UI and adapter contract are ready, but actual search results and audio playback require a compatible provider and permitted `streamUrl`/`previewUrl` values.
